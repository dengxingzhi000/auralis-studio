# Auralis Studio 用户手册

适用版本：**0.1.0**（Windows x64）
界面语言：简体中文（尚无 i18n）
最后更新：2026-10-22

> Auralis Studio 是一个本地音频分析工作台：文件波形、FFT 频谱、STFT 声谱图、
> 实时输入与 CSV/JSON 导出。
>
> 它**不是**校准级测量仪器。没有 SPL、LUFS、SNR、THD 或 THD+N；所有 dBFS
> 读数都相对于数字满刻度，没有声压校准。详见文末「已知限制」。

## 1. 系统要求与安装

| 项 | 要求 |
|---|---|
| 操作系统 | Windows 10/11 x64（开发与验证环境为 Windows 11 10.0.26300） |
| 磁盘 | 安装包与运行时约数百 MB（含 Electron/Chromium） |
| 音频设备 | 文件分析不需要声卡；实时输入需要一个 Windows 可用的输入设备 |
| 其他 | 无需单独安装 WebView2、Node.js 或 Rust |

安装包为 **NSIS 安装程序**，默认按当前用户安装，可选择安装目录，不需要管理员权限。
安装包目前**未签名**，Windows SmartScreen 可能显示「未知发布者」；这是预期行为，
不是安装包损坏。若组织策略禁止未签名程序，请使用源码构建。

卸载时默认**保留**用户数据（上次打开的文件、面板布局与显示偏好），
以便重新安装后继续使用；需要彻底清理时手动删除 Electron 的 userData 目录
（见[第 10 节](#10-数据布局与会话恢复)）。

> 分发包同时包含 `auralis-engine.exe`（Rust 音频引擎）与 Electron 运行时。
> 引擎位于安装目录的 `resources\engine\auralis-engine.exe`，由主进程自动启动，
> 不需要用户手动运行。

## 2. 第一次启动

1. 启动 Auralis Studio。
2. 点击顶部「打开文件…」，或把音频文件拖到窗口内。
3. 等待分析完成。状态栏会显示「分析中」；长文件可点「取消」或按 `Esc`。
4. 分析完成后，中央三块画布分别显示频谱、声谱图和波形，
   右侧检查器显示电平、指标与参数。
5. 上次成功打开的文件会在下次启动时自动重新分析（会话恢复）。

如果没有打开任何文件，也可以点顶部「合成信号」生成一段确定性的 1 kHz 正弦，
用于检查渲染与 IPC 通路。合成信号不会写盘。

## 3. 界面总览

```text
┌ 顶部命令栏：打开文件 · 合成信号 · 取消 · 实时采集 · 导出 · 面板开关 ┐
├ 左侧资源栏 ┬────────── 中央画布 ──────────┬──── 检查器 ────┤
│ 文件列表   │  频谱                          │ 电平            │
│ 实时输入   │  声谱图                        │ 信号指标        │
│            │  波形                          │ 峰值            │
│            │                                │ 参数 / 显示     │
├────────────┴────────────────────────────────┴─────────────────┤
│ 状态栏：任务 / 采样率 / 端到端 / 载荷 / 错误或提示              │
└────────────────────────────────────────────────────────────────┘
```

### 顶部命令栏

| 控件 | 作用 |
|---|---|
| **打开文件…** | 打开系统文件选择器（`Ctrl+O`） |
| **合成信号** | 生成确定性的 1 kHz 正弦并分析；用于验证链路 |
| **取消** | 仅在有文件分析任务时出现；中止当前任务（`Esc`） |
| **实时采集** | 展开左侧资源栏并滚动到「实时输入」面板 |
| **导出…** | 导出当前文件的分析结果（CSV 或 JSON） |
| **资源栏 / 检查器** | 显示或隐藏左右面板；状态持久化 |

### 状态栏

- 左端：当前分析任务（可取消），否则显示实时输入状态。
- **采样率**：当前文件或实时设备的采样率。
- **端到端**：最近一次文件分析的端到端耗时（Rust 计算 + IPC + 前端接收），
  **不是**音频设备的输入延迟。
- **载荷**：该次分析跨 IPC 传输的二进制视图数据大小。
- 右端：错误摘要或操作提示（例如导出成功、取消、会话恢复）。

## 4. 打开与管理文件

### 三种打开方式

1. 顶部「打开文件…」。
2. 左侧「打开音频文件…」。
3. 把文件从资源管理器拖到窗口。

三条入口走同一条分析路径，行为一致。

### 支持的格式

| 容器 | 能否解码 | 是否已验证 | 界面标记 |
|---|---|---|---|
| WAV | 是 | **是**（真实样本端到端） | 无 |
| FLAC | 是 | **是**（真实样本端到端） | 无 |
| MP3 | 是 | 否 | 「未验证」 |
| AIFF | 是 | 否 | 「未验证」 |
| OGG / Vorbis | 是 | 否 | 「未验证」 |

「未验证」表示容器能打开并解码，但尚未用真实样本完成端到端数值核对。
本项目不把「能解码」等同于「保证兼容」。不支持的格式会给出明确错误，不会崩溃。

FLAC 的验证样本在 `crates/auralis-codec/tests/fixtures/`（仓库内自带，
不依赖外部文件）；样本需要更新时按 crate 文档里的命令重新生成。

### 文件元数据

检查器「文件」分区显示容器、编码、采样率、声道数、时长和文件大小。
元数据通过只读文件头探测，读取是 O(1)，不会为了显示时长而解码整个文件。

### 大文件与内存

- PCM 按块解码，内存占用与文件长度解耦。
- 首次分析会附带**开头 30 秒**的频谱与声谱图。
- 声谱图后续时间窗通过「◀ / 开头 / ▶」、滚轮或拖动按需加载；
  Rust 只解码并计算目标窗口，内存与请求窗口成正比，而不是与整段音频成正比。
- 波形是 min/max 包络，不把全部 PCM 样本送到界面。

### 取消、失败与重试

- 分析中可以按 `Esc` 或点「取消」。**取消不是错误**：已有结果会保留，
  状态栏提示「已取消分析」。
- 失败时画布上方出现错误条，包含「重试」（`Ctrl+R`）与「关闭」。
- 错误条不会吞掉上一次成功的结果；修复文件或重新选择后可再试。

### 文件不完整（被截断）

文件头声明的时长大于实际存在的数据时（没下完、拷贝不完整），**分析照样完成**：

- 状态栏提示「文件不完整：已分析 X 秒（声明 Y 秒，缺 Z 秒）」；
- 所有结果（峰值、RMS、频谱、声谱图）只覆盖实际存在的那部分；
- 检查器里的时长仍是文件头声明的值，不会被换成更短的实测值；
- 导出文件的元数据里带 `truncated=true` 与声明时长。

这是**提示**而不是错误：已下载的部分依然可以测量，把它整份丢掉反而更糟。
真正损坏（容器头坏掉、编码不认识）才会报错。

## 5. 波形、频谱与声谱图

### 波形

- 显示整段文件的 min/max 包络，采样点数随画布宽度降采样。
- 立体声/多声道可在检查器「显示 → 声道显示」中切换：
  - **分道**：每个声道单独一条泳道；
  - **叠加（对比）**：所有声道叠在同一坐标系，用于看差异与相位问题。
- 当前版本尚不支持波形时间轴缩放与选区；视图聚焦于全局概览。

### 频谱

- 显示当前文件（或实时输入）的单边幅值谱，单位为 **dBFS**。
- 频率轴为**线性 Hz**；对数频率轴尚未实现。
- 鼠标悬停显示光标频率；峰值以标记显示。
- **实心峰值** = 由 FFT bin 直接测得；
- **空心/带「估算」标记** = 抛物线插值结果不可靠（扇贝损失较大，尤其在
  半 bin 偏移时）。估算读数仍会显示，但不应作为精确频率/幅值使用。
- 交互：
  - **拖拽框选**：放大到选中的频率范围；
  - **滚轮**：以光标位置为中心缩放；
  - **Shift + 拖拽**：平移视口；
  - **双击**：恢复到 0…奈奎斯特全带宽。
- 实时采集时，频谱切换为实时数据，带「实时」徽标；文件分析的峰值标记
  不会叠加到实时曲线上（两者频率位置不对应）。

### 声谱图

- STFT 参数：帧长 2048、hop 512（默认）。
- 低频在下方，高频在上方；颜色使用 inferno 色阶。
- 色阶与频谱共享同一个 dB 量程（检查器「显示 → dB 量程」），三块视图不会互相矛盾。
- 时间窗：
  - 「◀」向上一屏，「开头」回到 0 秒，「▶」向下一屏；
  - 在图上**滚轮**前后平移；
  - **拖动**按水平距离平移；
  - **双击**回到文件开头。
- 频率缩放：
  - **Shift + 滚轮**以光标所在频率为中心缩放；
  - **Shift + 拖拽**框选一段频段并放大；
  - 卡片头会显示当前频率范围，并有「频率复位」按钮恢复全带宽。
- 缩放是**裁剪**而不是拉伸：只画可见的那几行频率，并把它们铺满绘图区，
  因此放大后频率位置依然准确（不会得到一张被拉长的图）。
- 频谱与声谱图**共享**同一个频率视口：缩放其中一个，另一个会一起聚焦。
- 视口加载中会显示「载入…」；旧的过期请求会被取消，避免拖动时堆积。
- 声谱图只显示已计算窗口，文件末尾不足一帧的部分不会被补零。

### 电平表

- 每个声道一条 Peak 条，共享一个 RMS 标记。
- 颜色渐变覆盖整个轨道并**从右侧遮罩**，因此颜色位置始终代表绝对电平，
  短条不会把整条表染成绿色。
- 样本绝对值超过 1.0 时显示超量程警示。

### 电平 / 指标视图

中央画布最下面一张卡片（左侧「电平表 / 指标」入口直达），分三栏：

| 分区 | 内容 |
|---|---|
| 电平 | 逐声道 Peak 条与 RMS 标记；实时采集时显示当前读数 |
| 信号指标 | Peak、RMS、Crest（波峰因数）、DC Offset，以及本次分析用的 FFT 点数与窗 |
| 数据质量 | 超量程样本、平顶片段、清理样本、包络点数、文件完整性 |

- 静音文件的 Peak / RMS 显示成「—」而不是 0：0 会被读成「有信号但极小」，
  而静音是真的没有信号。
- **文件完整性**一行在文件被截断时会写出「声明时长 vs 实际解码时长」，
  并提示只分析了文件里实际存在的那一部分。

### 显示选项

检查器「显示」分区，所有选项持久化到 `localStorage`：

| 选项 | 取值 | 说明 |
|---|---|---|
| 频谱形态 | 填充（面积） / 曲线（声线） | 曲线模式更适合看低电平细节；填充会把 −100 dB 以下染色 |
| dB 量程 | −140…0 / −100…0 / −80…−10 / −140…−40 | 同时作用于频谱、声谱图与电平表 |
| 声道显示 | 分道 / 叠加 | 用于波形；叠加便于看声道差异 |
| 复位缩放 | 按钮 | 频谱回到全带宽 |

当前量程与视口范围在检查器中以数值显示，便于复现截图或导出参数。

## 5.1 偏好设置、全局搜索、帮助与关于

这四个入口此前是禁用状态，现在都可用。

### 偏好设置（`Ctrl+,`）

左侧「工程 → 偏好设置」或 `Ctrl+,` 打开。

| 分区 | 项 |
|---|---|
| 显示 | 频谱形态、dB 量程、声道显示（与检查器「显示」分区是同一份设置） |
| 布局 | 显示 / 隐藏左侧资源栏与右侧检查器 |
| 分析 | 包络点数（512 / 1024 / 2048 / 4096）、启动时恢复上次打开的文件 |
| 数据 | 重置显示与分析偏好、重置面板布局、清除会话记录 |

- 设置保存在本机 `localStorage` 的 `auralis.prefs.v1`，改完立即生效。
- **包络点数**同时用于分析与导出：导出的 CSV 用的是同一个值，
  所以屏幕上的波形与导出的数据始终一致。
- 「重置面板布局」会把侧栏宽度与可见性恢复默认。

### 全局搜索（`Ctrl+K` / `Ctrl+F`）

命令面板，分三组：

- **文件**：本次会话打开过的文件，回车直接重新分析；
- **峰值**：当前文件的检测峰值，回车把频率视口对准它并移动频率游标；
- **操作**：打开文件、导出、生成合成信号、复位缩放、显示 / 隐藏两侧栏，
  以及偏好设置、帮助与关于。

匹配规则：大小写不敏感；多个词是「都要命中」；分组名与右侧说明也参与匹配。
↑↓ 选择、Enter 执行、Esc 关闭。

### 帮助（`F1`）

包含界面导览、完整快捷键表、术语表（dBFS / RMS / Crest / DC Offset / STFT /
扇贝损失 / 超量程）与能力边界声明。

### 关于（左下角 `⋮`）

显示应用版本、算法版本、DSP 规范修订，以及容器运行时版本
（Electron / Chromium / Node.js）与第三方许可声明。


## 6. 实时输入

### 启动与停止

1. 点顶部「实时采集」，或直接在左侧资源栏找到「实时输入」。
2. 在设备下拉框选择输入设备；面板会显示设备声道数。
3. 点「开始采集」。成功后显示采样率、声道、已处理帧数、两项丢帧计数。
4. 点「停止采集」结束会话。隐藏资源栏不会中断采集；重新显示时面板会接管现有会话。

如果本机没有输入设备，面板显示「未发现输入设备」——在没有声卡的环境里这是正常状态，
不是程序错误。

### 实时链路

```text
WASAPI 回调 → 有界无锁环形缓冲 → 分析线程（FFT/峰值/RMS）→ 最新快照
                                                    ↑
                                     界面每 33 ms 拉取一次
```

- 音频回调只做「取缓冲 → 拷贝 → 入环 → 计数」，不做 FFT、不加锁、不等待界面。
- FFT 全部在分析线程完成。4096 点 FFT 在基准机上约 271 µs，而 48 kHz 回调预算
  约 20.8 µs；把 FFT 放进回调会超预算 13 倍。
- 界面刷新约 30 Hz，与音频回调频率解耦。
- 快照先按显示需要降采样（1024 bin × f32，约 4 KB），以二进制跨 IPC 传输。

### 两项丢帧计数

| 计数 | 含义 | 正常吗 |
|---|---|---|
| **分析丢帧**（`droppedFrames`） | 环形缓冲满，最新样本被丢弃 | 应为 0；持续增长说明分析线程跟不上 |
| **快照覆盖**（`snapshotOverwrites`） | 分析线程发布的新快照比界面拉取更快，旧快照被覆盖 | 常见且通常无害；界面本来就只画最新一帧 |

两者都不是「音频样本损坏」的同义词，也不应该为了好看而隐藏。

### 设备格式协商

应用会按设备声明支持的 f32 格式协商采样率与声道数；请求值不可用时回退到设备默认值，
并**显示实际使用的格式**。频率轴使用实际采样率，因此不会因为回退而整体偏移。

多声道输入按各声道**平均**混成单声道用于频谱。完全反相的立体声
（L = +1，R = −1）混音后是数字静音，界面显示「—」而不是一个假读数。

### 实时限制

- 已在**一台机器、一个 Realtek WASAPI 默认输入、2 声道 / 48 kHz、6 秒运行**中验证：
  处理 287,040 帧（0.991 × 实时）、丢帧 0、快照 RPC p95 3.10 ms。
- **设备热插拔、运行中切换设备、8 小时连续运行尚未验证。**
- 未启用 ASIO。CPAL 的 ASIO 后端需要单独下载的 Steinberg ASIO SDK，
  默认构建不包含；详见 [ADR-020](ADR.md#adr-020实时高频通道与-asio-评估)。
- Windows 的麦克风隐私设置可能阻止采集：如果设备存在但始终无数据，
  打开「设置 → 隐私和安全性 → 麦克风」，确认桌面应用有权访问输入设备。
- 独占模式或其他应用占用设备时，启动可能失败；关闭占用程序后重试。

## 7. 指标与数据质量

检查器「信号指标」分区：

| 指标 | 定义 | 单位 |
|---|---|---|
| **Peak** | 样本绝对值最大值（逐声道统计，界面显示最大值） | dBFS |
| **RMS** | 均方根，统计窗口为整段文件 | dBFS |
| **Crest** | Peak − RMS | dB |
| **DC Offset** | 每声道样本平均值 | FS（满刻度归一化） |
| **CHn Peak** | 多声道时逐声道峰值；静音显示「—（静音）」 | dBFS |
| **超量程样本** | `|x| > 1.0` 的样本数（数字过载） | 个 |
| **平顶片段** | 启发式平顶计数 | 个 |
| **清理样本** | NaN/Inf 被替换为 0 的数量 | 个 |

重要说明：

- `0 dBFS` 是数字满刻度，**不是**校准声压级。没有麦克风灵敏度、参考声压或
  测量带宽，就不能把 dBFS 换成 SPL。
- **平顶片段当前在命令层恒为 0**：真正的逐样本平顶检测需要完整样本轨迹，
  与分块、限内存的解码路径冲突。该字段是已知占位限制，不代表「没有削波」。
  超量程样本计数是真实的，可作为数字过载的证据。
- 非有限值（静音导致的对数结果为 −∞ 等）不会被写成 0；导出时 JSON 用 `null`、
  CSV 用空字段表示，并记录 `non_finite_values` 计数。

峰值列表：

- 最多显示 8 个峰值；
- 显示频率、dBFS、FFT 点数、窗函数与 Hz/bin；
- 插值不可靠时标注「估算」，悬停可看扇贝损失 dB。

## 8. 导出 CSV / JSON

### 操作

1. 打开并成功分析一个文件。
2. 点顶部「导出…」。
3. 在保存对话框中选择 `.csv` 或 `.json`。
4. 状态栏显示导出格式、字节数与目标路径。

扩展名决定格式；Rust 侧会校验扩展名与请求格式一致。删除扩展名时界面会补 `.csv`；
**不会**写出「后缀是 .json 的 CSV」。

### 内容与可追溯性

导出会在 Rust 侧**重新跑一遍同一条分析路径**，而不是把屏幕上的降采样数据拼回去。
因此：

- 导出内容与界面同源，但拥有完整精度；
- 代价是一次重新解码，长文件需要等待；
- 导出可独立复现，不依赖当前 UI 状态。

CSV 是长格式表：

```text
series,index,x_hz,x_s,value,unit,quantity
```

文件开头有 `#` 元数据块，包含应用版本、算法版本、DSP 规范修订、单位、
FFT 参数、声谱图网格、hop、源文件、解码器与采样率。

源文件被截断时，元数据里额外带 `truncated=true` 与 `declared_duration_s`
（文件头声明的时长），而 `duration_s` 是实际参与分析的时长。
拿截断文件的导出和完整文件比对时，差异来源因此说得清楚。

JSON 在顶层声明 `units`，并携带同样的参数与来源信息。

### 数值约定

- 静音/非有限值：JSON `null`、CSV 空字段，绝不写成 `0`。
- `non_finite_values=<n>` 报出计数。
- 波形包络的来源如实标注为「第一个声道的按桶最大值」，
  不是所有声道的 min/max。
- 导出的 dBFS 同样是数字满刻度参考，不做 SPL 校准。

## 10. 数据、布局与会话恢复

### 隐私

- 所有音频处理都在本机完成；应用不会上传音频、指标或文件路径。
- 没有遥测、账号或云同步。
- 文件选择器与保存对话框由 Electron 主进程调用系统对话框。

### 持久化内容

| 数据 | 位置 | 内容 |
|---|---|---|
| 布局 | 渲染进程 `localStorage` | 左右面板可见性、面板尺寸 |
| 显示偏好 | `localStorage` 键 `auralis.display.v1` | 频谱形态、dB 量程、声道布局 |
| 上次文件 | `localStorage` 键 `auralis.session.v1` | 最近一次成功打开的文件路径 |
| 运行标记 | Electron userData 目录 `auralis-running.lock` | 判断上次是否正常退出 |

userData 在 Windows 上通常位于 `%APPDATA%` 下与应用名对应的目录。
卸载默认保留这些数据；需要清空时请手动删除。

### 会话恢复

- 正常退出后重启：自动重新分析上次成功打开的文件，状态栏提示「已恢复上次打开的文件」。
- 强制结束/崩溃后重启：检测到运行标记仍在，提示「上次会话未正常结束，已恢复」。
- 恢复的是**文件与分析**，不是崩溃瞬间的内存状态；分析中崩溃会在重启后重新跑一遍
  （结果可复现，代价是一次解码）。
- 如果文件已被移动或删除，恢复会按普通打开错误呈现。

## 11. 故障排查

| 现象 | 可能原因 | 处理 |
|---|---|---|
| SmartScreen「未知发布者」 | 安装包未签名 | 确认来源后选择「更多信息 → 仍要运行」；或使用源码构建 |
| 「无法启动音频引擎」 | 安装不完整、杀毒软件隔离、引擎路径缺失 | 重新安装；确认 `resources\engine\auralis-engine.exe` 存在 |
| 打开文件报「格式未验证」 | FLAC/MP3/AIFF/OGG 未完成真实样本验证 | 可继续分析，但不要把结果当作已认证兼容性 |
| 状态栏提示「文件不完整：已分析 X 秒」 | 文件没下完或拷贝不完整，文件头声明的时长大于实际数据 | 分析已完成但只覆盖已下载部分；提示里的「缺 Z 秒」是缺失量，末尾缺几十毫秒可忽略，缺几秒建议重新获取 |
| 提示「文件已损坏」 | 容器头损坏、编码不受支持 | 用播放器交叉验证；点「重试」或换文件 |
| 实时面板没有设备 | 无声卡、驱动未加载、权限被拒 | 检查设备管理器与 Windows 麦克风隐私设置 |
| 实时启动失败 | 设备被独占/采样率不支持 | 关闭占用程序；应用会回退并显示实际格式 |
| 分析丢帧持续增长 | CPU 过载、设备缓冲过小 | 关闭高负载程序；报告设备与配置 |
| 「engine busy」 | 同时提交了过多慢任务 | 等待当前分析/导出完成 |
| 声谱图空白/停在 30 秒 | 视口未加载或请求被取消 | 用 ◀ / ▶ 或滚轮切换窗口 |
| 窗口花屏/闪烁 | GPU/驱动/合成器问题 | 更新显卡驱动；记录 GPU 型号并反馈（见 ADR-019） |

## 12. 已知限制

按重要性排序，均为当前版本的**诚实限制**：

1. **不是校准仪器**：没有 SPL、LUFS、SNR、THD、THD+N；不作任何测量准确度承诺。
2. **只有 WAV 与 FLAC 经过真实样本验证**：MP3/AIFF/OGG 可解码但未验证。
3. **平顶片段恒为 0**：命令层的启发式检测尚未接入逐样本轨迹；
   超量程样本计数仍然有效。
4. **实时输入只在单机单设备上验证**：热插拔、设备切换、8 小时连续运行未验证；
   未启用 ASIO。
5. **界面为 30 Hz 快照刷新**：满足 20–60 次/秒目标；更高刷新率未实现，
   也没有证据表明需要。
6. **频谱为线性频率轴**：对数频率轴尚未实现。
7. **波形不支持时间缩放/选区**；声谱图支持 30 秒窗口平移。
8. **UI 仅中文**；macOS/Linux 未适配。
9. **安装包未签名**，没有自动更新。
10. **Electron 容器只在一台机器/GPU 组合上验证**，不构成对所有硬件的保证。
11. **FFT 4096 中位数 271 µs**，高于设计文档早期写的 100 µs 目标；
    当前不宣称任何 FFT 性能指标。
12. **长时间稳定性**只有短时 soak 验证，尚无 8 小时实测。
