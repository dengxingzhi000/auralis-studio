# 测试与验收计划

## 1. 测试层级

1. 单元测试：DSP 公式、窗函数、频率映射、错误边界。
2. 集成测试：解码到分析、任务取消、结果导出、缓冲溢出。
3. UI/桌面测试：文件导入、布局调整、设备错误、窗口缩放。
4. 性能测试：FFT、STFT、波形包络、纹理更新、内存上限。
5. 发布测试：Windows Release、安装/卸载、依赖和许可证审查。

## 2. 合成信号集

至少包含：
- 全零信号；
- 常量 DC 信号；
- 相干采样正弦波；
- 非整数周期正弦波；
- 多音信号；
- 近 Nyquist 信号；
- 左右声道不同频率/幅值；
- 超量程浮点信号；
- 含 NaN/Inf 的无效输入；
- 极短输入和不完整多声道帧。

测试样本、生成脚本和预期值应纳入仓库，避免依赖外部临时文件。

## 3. 文件解码测试

每种宣称支持的容器/编码组合至少有：
- 正常文件；
- 空文件或截断文件；
- 损坏头信息；
- 多声道文件；
- 非 44.1/48 kHz 采样率文件；
- 长文件或大文件；
- 元数据缺失的文件。

不支持的格式必须明确报错，不得崩溃。

## 4. 实时音频测试

- 无输入设备；
- 设备启动失败；
- 支持格式协商失败；
- 设备拔出/切换；
- Ring Buffer 满；
- 工作线程短暂落后；
- 连续采集至少 8 小时的稳定性目标；
- UI 高频操作时采集仍保持可观测的稳定状态。

物理设备测试应在具有真实 Windows 音频设备的专用环境运行。普通 CI 不应假设一定有音频设备。

## 5. 初始验收目标

- 所有核心 DSP 算法有测试。
- 关键算法具有参考值、容差和边界测试。
- 核心模块行覆盖率目标 ≥ 80%，但覆盖率不能代替数值验证。
- 常规交互目标 60 FPS；实际以约定测试机和视图复杂度验收。
- 实时显示目标 20–60 次/秒，和音频设备采样回调分离。
- 实时连续运行 8 小时无崩溃、无持续内存增长。
- 取消任务后停止后续处理并释放资源。
- Windows Release 构建可重复。

## 6. 基准记录

每份基准记录：
- CPU、内存、OS 版本；
- Rust 工具链、编译 profile；
- crate 版本和 Cargo.lock；
- 输入样本率、通道数、样本数；
- FFT/STFT 参数；
- 运行次数、均值和分位数；
- 预期结果和实际结果。

## 7. CI 命令

- `cargo fmt --all -- --check`
- `cargo clippy --workspace --all-targets -- -D warnings`
- `cargo test --workspace`
- `cargo build --workspace --release`

在 workspace 完成初始化后，将以上命令接入 Windows GitHub Actions。根据实际 target 与依赖情况调整矩阵。
