## 1. 意图与动机

应用左侧资源栏的「分析视图」与「工程」分组里，有 8 个入口仍是**禁用并标注里程碑**的状态：

| 入口 | 当前状态 | 目标 |
|---|---|---|
| 声谱图缩放 | 禁用 · M3 | 声谱图频率轴缩放，与频谱共享视口 |
| 电平表 / 指标 | 禁用 · M2 | 中央画布新增「电平 / 指标」视图 |
| 后台任务队列 | 禁用 · M3 | 左侧栏任务队列面板（运行中 + 最近完成） |
| 实时输入 | 禁用 · M4 | 导航指向已存在的实时采集面板 |
| 偏好设置 | 禁用 · M5 | 偏好设置对话框 |
| 搜索 | 禁用 · M5 | 全局搜索面板（文件 / 峰值 / 操作） |
| 帮助 | 禁用 | 帮助对话框（快捷键、导览、术语、边界） |
| 关于与版本信息 | 禁用 | 关于对话框（版本、运行时、许可声明） |

这些功能背后的**计算能力大多已经存在**（Rust 侧 `task_queue`、`cancel_task`、`app_info`
命令已实现；实时采集面板已可用；搜索面板 `SearchPalette.tsx` 已在树内但未接线）。
缺的是**界面表达**，不是算法。因此本轮**不需要改动任何 Rust crate**——这是本设计
最重要的一条约束：ADR-018 的三条硬规则天然不受影响，因为没有新的数据通路。

## 2. 目标与非目标

### 目标

1. 上述 8 个入口全部可用，且每个入口点下去都产生**真实可见**的结果。
2. 新视图遵守 [UI_SPEC §3](../../UI_SPEC.md) 的分区：中央画布放波形/频谱/声谱图/电平表/指标，
   左侧资源栏放文件/设备/任务。
3. 不引入新的音频计算：所有读数继续由 Rust 侧给出，前端只做展示与调度。
4. 保持既有交互不回退：当前已工作的拖放、取消、导出、平移、缩放行为不变。

### 非目标

- 不做 LUFS / SNR / THD / THD+N 等 PRD §V1.5 才有的高级指标（AGENTS 明确禁止
  在算法与前提未实现前给出这类数字）。
- 不做批量分析、多窗口、可停靠面板系统。
- 不改 Rust 侧任何 crate；不新增 IPC 命令（`task_queue` 已存在且已在快命令泳道）。
- 不做深色主题之外的第二套配色；不引入新的运行时依赖（无图标库、无 UI 框架）。

### 反目标（做成了算失败）

- 出现「点得动但没反应」或「显示假数据」的控件。
- 前端出现任何 dB 换算 / FFT / 峰值检测（违反 ADR-018 规则 1，
  `scripts/check-boundaries.ps1` 会机械拦截 `Math.log10` 等）。
- 声谱图缩放只是**拉伸**整张矩阵（那不是缩放，只是拉伸，读数仍是错的）。
- 缩放后频率刻度仍标全带宽（缩放后坐标轴不跟着变 = 读数错误）。

## 3. 硬约束

| 约束 | 来源 | 对本设计的影响 |
|---|---|---|
| 前端不得参与音频计算 | ADR-018 规则 1 | 缩放、裁剪只作用于**已算好的** dB 数组；新指标全部复用现有 Rust 返回值 |
| 二进制优先 | ADR-018 规则 2 | 本轮不新增二进制载荷 |
| 频率与数据量反比 | ADR-018 规则 3 | 频谱点数仍随画布宽度走 |
| 只用设计令牌 | ADR-017 | 新样式全部 `var(--token)`，组件内不写死颜色 |
| 未实现的功能保持禁用并标注 | UI_SPEC §4 | 8 个入口全部真正实现后才解除禁用与里程碑标记 |
| 不宣称未验证的格式 | AGENTS / PRD §8 | 关于与帮助里保留「仅 WAV 已用真实样本验证」的声明 |

## 4. 逐项设计

### 4.1 声谱图缩放（M3）

**问题**：声谱图的频率轴永远是全带宽。2048 点 STFT 在 44.1 kHz 下 bin 间隔
≈ 21.5 Hz，而奈奎斯特 22.05 kHz 对应 1024 个 bin——一个 1 kHz 正弦只占**一个** bin，
在 500 px 高的绘图区里不到 0.5 px，屏幕上等于看不见。声谱图因此「有数据但读不出东西」。

**做法**：给声谱图加**频率视口**，与频谱图**共享同一份 `viewRange` 状态**。

- `SpectrogramView` 新增两个 prop：
  - `viewRange?: [number, number] | null` —— 可见频率区间（Hz），`null` = 全带宽；
  - `onViewRangeChange?: (r: [number, number]) => void`。
- 绘制时**裁剪** bin 区间而不是缩放整张图：把 `[lo, hi]` 映射到 bin 下标
  `floor(lo / binHz)` .. `ceil(hi / binHz)`，只把这些 bin 贴到绘图区。
  这样放大后看到的仍是真实频率位置。
- 频率刻度按 `viewRange` 重新标注，不再固定 0…奈奎斯特。
- 交互（与现有时间轴交互共存，不冲突）：
  | 操作 | 行为 |
  |---|---|
  | 滚轮 | 平移时间（既有） |
  | `Shift` + 滚轮 | 以光标所在频率为中心**缩放频率** |
  | 拖拽 | 平移时间（既有） |
  | `Shift` + 拖拽 | 框选频率区间 → 缩放到该区间 |
  | 双击 | 回到文件开头（既有，不改） |
  | 卡片头「频率复位」按钮 | 恢复全带宽（仅在已缩放时出现） |
- 与频谱共享：`App.tsx` 里已有的 `viewRange` / `setViewRange` 同时喂给
  `SpectrumView` 与 `SpectrogramView`。频谱的「复位缩放」因此同时复位声谱图。
- 底部说明条补充新交互提示。

**为什么共享而不是各自一份**：频谱与声谱图是同一份信号的两个投影。用户「盯着
1–2 kHz 看」时，两个视图应当一起聚焦；各自一份会出现频谱看 1 kHz、声谱图看全带的割裂。
UI_SPEC §4 已有「频谱与声谱图共享频率游标」的先例，这是同一原则的延伸。

### 4.2 电平表 / 指标（M2）

**做法**：中央画布新增第 4 张卡片「电平 / 指标」，是 `UI_SPEC §4` 里
`AnalysisSummaryView`（指标、单位、参数、数据质量诊断）的实体化。

- 卡片内容三列：
  1. **电平表**：复用 `LevelMeter`（逐声道 Peak 条 + RMS 标记 + 超量程警示），
     实时采集时显示实时读数。
  2. **信号指标**：Peak / RMS / Crest / DC Offset / 逐声道 Peak。
  3. **数据质量**：超量程样本 / 平顶片段 / 清理样本 / 解码帧数 / 包络点数 / FFT 与窗；
     文件被截断时额外显示「完整性」行（声明时长 vs 实际解码时长）。
- 所有数值来自已有的 `FileAnalysis` 返回值，**不新增 Rust 接口**。
- 布局：`.center-stack` 改为可纵向滚动；三张图表卡片给 `min-height`，
  新卡片高度按内容自适应。窗口变矮时用户滚动，而不是把图表压成条带。
- 检查器里**保留**现有的「电平 / 信号指标」分区（紧凑读数常驻可见），
  与新卡片共享同一份数据，不重复计算。

### 4.3 后台任务队列（M3）

**做法**：左侧栏新增 `TaskQueuePanel`，数据来自**已存在的** `task_queue` 命令。

- `task_queue` 是**快命令**（在 RPC 读取线程内联执行，不排在慢任务后面），
  返回运行中任务的 `{taskId, kind, label, elapsedMs}`。
- 面板分两段：
  - **运行中**：类型徽标（分析 / 声谱图）、标签、实时已运行时长、「取消」按钮
    （复用 `cancel_task`）。
  - **最近完成**：前端在本次会话内记录的**已完成文件分析**（完成 / 已取消 / 失败 +
    耗时），最多 8 条。Rust 侧只暴露运行中任务，历史由前端补。
    **不收录声谱图视口任务**——自动平移会连发这类请求，进历史会刷屏。
- 轮询 500 ms 一次（快命令，开销可忽略），导航项上显示运行中任务数徽标。
- 面板默认折叠；有任务运行时自动展开；导航项点击可手动展开/折叠并滚动到面板。

### 4.4 实时输入（M4）

**做法**：实时采集面板（`RealtimePanel`）早已可用且能工作，缺的只是**导航入口**。

- 导航项「实时输入」解除禁用，点击后滚动到实时面板并高亮。
- 采集中时导航项显示「采集中」状态点。
- 不改动 `RealtimePanel` 内部逻辑。

### 4.5 偏好设置（M5）

**做法**：偏好设置对话框 + 统一的偏好存储。

- 新增 `lib/prefs.ts`：读写 `auralis.prefs.v1`，**并从旧的 `auralis.display.v1`
  迁移**（旧键仍在时读它，读到后写新键；之后只用新键）。用户已有的显示偏好不丢。
- 对话框分区：
  | 分区 | 项 |
  |---|---|
  | 显示 | 频谱形态、dB 量程、声道显示（与检查器「显示」分区同源同状态） |
  | 布局 | 资源栏可见、检查器可见 |
  | 分析 | 默认包络点数（512 / 1024 / 2048 / 4096）、启动时恢复上次文件 |
  | 数据 | 清除本地偏好、清除会话记录 |

### 4.6 搜索（M5）

**做法**：接线树内已有的 `SearchPalette.tsx`。

- 快捷键 `Ctrl+K` / `Ctrl+F`。
- 搜索项分三组：
  - **文件**：本次会话打开过的文件 → 重新分析。
  - **峰值**：当前文件的检测峰值 → 把频率视口对准该峰值（±若干 bin）并滚动到频谱。
  - **操作**：打开文件、导出、生成合成信号、复位缩放、显示/隐藏资源栏、
    显示/隐藏检查器、偏好设置、帮助、关于。
- 搜索只做**字符串匹配与展示切换**：不解析音频、不做任何数值换算。

### 4.7 帮助

**做法**：帮助对话框，内容取自 UI_SPEC §6.2 与 PRD，不新造事实。

- 分区：快捷键表、界面分区导览、术语表（dBFS / RMS / Crest / DC Offset / STFT /
  扇贝损失 / 超量程）、能力边界声明（不提供校准 SPL、不做 LUFS、仅 WAV 已验证）。
- 快捷键 `F1`。

### 4.8 关于与版本信息

**做法**：关于对话框。

- 内容：应用版本、算法版本、DSP 规范修订（均来自 `app_info`）；
  容器运行时版本（Electron / Chromium / Node，来自 preload 的 `container`）；

- 入口：左下角 `⋮` 图标按钮（解除禁用）+ 搜索面板里的「关于」操作项。

## 6. 已确定的事项（含评审后拍板）

### 6.1 实现层面的决定

| 事项 | 决定 | 理由 |
|---|---|---|
| 声谱图缩放的轴 | 频率轴（不是时间轴） | 时间轴已有 30 s 窗口平移；频率轴才是「看不清」的那一维 |
| 缩放交互的修饰键 | `Shift` | 滚轮/拖拽已被时间轴占用；`Shift` 是唯一不冲突的组合 |
| 双击语义 | 保持「回到文件开头」 | 既有已文档化行为，不做破坏性改动；频率复位用独立按钮 |
| 频谱与声谱图的视口 | 共享一份 `viewRange`，各自按自己的奈奎斯特钳位 | 同一信号的两个投影应当一起聚焦；实时态下两者采样率不同，按各自奈奎斯特钳位即可保持「同一个 Hz 频带」 |
| 声谱图频率轴的采样率 | 用**文件自己的** `display.sampleRate`，不用实时设备采样率 | 现状下实时采集开着时声谱图画的是文件的矩阵、频率轴却标设备奈奎斯特，读数是错的。频率视口依赖正确的频率轴，必须一并修 |
| 打开新文件 / 采样率变化 | 重置 `viewRange` 为 `null`（全带宽） | 否则新文件的频率轴与旧视口不匹配，可能裁出空白区 |
| 偏好键 | 新键 `auralis.prefs.v1`（显示 + 布局可见性 + 分析默认值 + 会话恢复开关），从 `auralis.display.v1` 与 `auralis.workspace.visibility.v1` 迁移 | 单一真值源；不丢用户已有偏好 |
| 面板宽度键 | 仍归 `auralis.workspace.widths.v1`（`Workspace.tsx` 自持） | 宽度是拖拽结果不是「偏好」，且 `Workspace` 组件自持读写 |
| 任务历史 | 前端会话内记录，**只收录 `analyze` 类**（文件分析） | 声谱图视口请求会在自动平移时连发，进历史会刷屏、挤掉用户真正关心的文件分析 |
| 任务 outcome 来源 | 前端持有 promise，用返回的 `outcome` 字段（`succeeded` / `cancelled` / `failed`） | Rust 侧只暴露运行中任务，历史只能由前端结算 |
| 导航项点击语义 | 统一为「滚动到对应卡片/面板」；波形、频谱两项也一并改为可点击 | 现状是 `active` 但点了没反应，本身就是「看起来能用但没功能」 |
| 锚点 | DOM `id` + `scrollIntoView` | 中心画布改为可滚动后需要稳定锚点 |
| 实时采集状态指示 | 给 `RealtimePanel` 增加 `onStatusChange` 回调 | 用 `liveDb != null` 近似会在「采集中但静音」时让状态点消失 |
| 检查器里的电平/指标 | 保留 | 紧凑读数常驻可见有价值；新卡片是完整视图，二者共享同一份数据 |
| 搜索峰值的视口宽度 | 半宽 = `max(250 Hz, 6 × 声谱图 bin 宽)`，中心取 `peak.binFrequencyHz` | 用分析 bin 频率定位（真实峰位），用绝对 Hz 定宽度，避免「用显示 bin 算宽度」导致声谱图只剩一两个 bin |
| 前端测试运行器 | **不引入** vitest 等新 devDependency | 仓库目前没有任何前端测试设施；AGENTS「不预建」原则。为可测性，把偏好校验、bin 裁剪与频率映射拆成**无 DOM 依赖的纯函数**，将来加运行器可直接覆盖 |
| 文件截断字段 | **纳入**新「数据质量」卡片 | 「只分析了文件的一部分」必须在界面上可见；与并行落地的截断字段（`truncated` / `declaredDurationSeconds` / `decodedDurationSeconds`）同源 |
| 包络点偏好 | 同时用于 `export_analysis` | 否则导出与屏幕显示不一致（导出是屏幕数据的来源） |

### 6.2 「清除」按钮的口径（精确到键）

| 按钮 | 删除的键 | 效果 |
|---|---|---|
| 重置显示与分析偏好 | `auralis.prefs.v1`、`auralis.display.v1` | 显示/分析项回默认，内存态立即复位 |
| 重置面板布局 | `auralis.workspace.visibility.v1`、`auralis.workspace.widths.v1` | 侧栏宽度与可见性回默认 |

### 6.3 评审发现的事实更正（实现必须遵守）

1. **声谱图矩阵是 512 个 bin，不是 1024。** `SPECTROGRAM_BINS = 512`
   （`file_commands.rs`），源 STFT 的 1025 个 bin 被 `Stft::to_matrix` 聚合。
   因此 `binHz = nyquistHz / spectrogramBins`，**不得硬编码 1024**。
   动机结论不变：1 kHz 正弦仍只占不到一个 bin。
2. **`scripts/check-boundaries.ps1` 拦截小写字面量 `fft(`、`hann(`、`Math.log10`、
   `Math.log2`、`new Float64Array`。** 新代码与注释都不得出现这些序列。
3. 声谱图的 bin 网格**不随画布宽度变**（固定 512），所以 §4.1 的裁剪是纯前端
   裁剪，不需要新的降采样规则。
